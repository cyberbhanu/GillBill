# GillBill deployment: Vercel and Render

GillBill is a full-stack Next.js app: its pages and `/api/*` backend routes are
deployed together to Vercel or Render. Browser requests use same-origin `/api/*`
paths, so production does not call the developer's `localhost:3000`. Deploying
to both creates two complete app instances; it does not make Render a separate
backend for Vercel. Both instances can share MongoDB Atlas and Vercel Blob.

## Before deploying

1. Push this project to a GitHub repository. Neither hosting service can deploy
   this local folder until it is connected to a Git repository.
2. In MongoDB Atlas, create a cluster, add a database user under **Database
   Access**, and add the app's deployment egress addresses under **Network
   Access**. Copy the cluster's `mongodb+srv://` connection string and replace
   its database name with `gillbill`. Encode special characters in the password
   for use in a URL. Atlas clusters provide the replica set required by GillBill
   transactions.
3. Create a Vercel Blob store and copy its read/write token.
4. Set a long random `AUTH_SECRET`. Keep the production secrets private.

## Vercel

1. Import the GitHub repository in Vercel and use the repository root.
2. Vercel reads `vercel.json`, synchronizes the Prisma schema to MongoDB with
   `prisma db push`, then builds with `pnpm build:deploy`.
3. Add `DATABASE_URL`, `AUTH_SECRET`, and `BLOB_READ_WRITE_TOKEN` in the Vercel
   project environment variables for Production (and Preview if needed). Set
   `APP_URL` to `https://gill-bill.vercel.app` for canonical links. Keep the
   same `AUTH_SECRET` on Render if users should be able to sign in consistently
   on both app domains; each domain still has its own browser session cookie.
4. Deploy. The configured build command synchronizes the MongoDB collections
   and indexes before each build.

## Render

1. In Render, create a Blueprint from the GitHub repository and select the
   included `render.yaml`.
2. Add the same `DATABASE_URL` and `BLOB_READ_WRITE_TOKEN` used by Vercel when
   both apps should share data and images. `AUTH_SECRET` is generated by the
   Blueprint; set it to the Vercel value if you need consistent auth settings.
   Render provides `RENDER_EXTERNAL_URL` for password-reset links. To override
   it, set `APP_URL` to the Render service's own HTTPS URL.
3. Deploy. The start command synchronizes the MongoDB schema before starting
   Next.js.

## Notes

- `prisma/schema.mongodb.prisma` is the production schema. Keep it in sync with
  `prisma/schema.prisma` whenever the data model changes. MongoDB does not use
  Prisma Migrate; `prisma db push` applies schema and index changes.
- The first deployment initializes collections in MongoDB. It does not copy
  data from the local `prisma/dev.db` file or an existing PostgreSQL database.
- Local development and production generate Prisma Client from
  `prisma/schema.mongodb.prisma`; set `DATABASE_URL` in the ignored `.env` file
  before starting GillBill locally.
- MongoDB Atlas must allow inbound connections from both hosting services. If
  Atlas cannot allowlist their egress addresses, configure Atlas Network Access
  deliberately before deployment; do not put database credentials in Git.
- Without `BLOB_READ_WRITE_TOKEN`, image uploads use the local filesystem. That
  is suitable for development only; deployed instances can lose those files.
- Vercel and Render are separate deployments. Each has its own domain, logs,
  and environment settings even when both connect to the same database.
- The public Vercel URL is `https://gill-bill.vercel.app`; password-reset links
  use the configured `APP_URL` or the hosting provider's deployment URL.
